# 销售客户管理与跟进系统 Phase 实施计划

## 计划边界

本计划只实施现有销售功能的质量治理，不新增客户、线索、商机、报价、产品目录、ERP、AI 或移动端功能。

## Phase 1：治理基础

### 目标

让关键业务操作可以记录、定位和验证，让发布和数据库检查有统一入口。

### 工作项

1. 审计基础
   - 新增结构化审计数据模型。
   - 提供统一审计写入方法。
   - 接入客户、客户归属、公海、订单、回款、合同和文件访问等关键写入/下载路径。
   - 敏感字段过滤，不记录密码、令牌和完整敏感凭据。

2. 日志和错误治理
   - 为请求生成可追踪的 `requestId`。
   - 错误日志统一写入 `logs/`。
   - 对外错误只返回通用信息和 `requestId`。
   - 详细错误只进入服务端日志。

3. 数据质量检查
   - 检查 Prisma schema 和迁移状态。
   - 检查客户重复电话/邮箱、订单金额关系、合同最新版本和关键外键关系。
   - 检查备份文件完整性和 SHA-256。
   - 检查线上服务、数据库和备份定时器状态。

4. 运行入口
   - 通过 `python scripts\manage.py ...` 执行类型检查、构建、路由检查、数据审查和冒烟检查。
   - 所有脚本输出写入 `logs/`。
   - Windows 环境和 shell 环境分别保留可用入口。

### 验收标准

- 关键操作能在审计表中查询到操作人、时间、对象和结果。
- 请求失败时，页面只看到可理解的错误和 `requestId`，不暴露堆栈或服务器路径。
- 数据质量检查能在发现问题时返回非零退出码，不能把异常报告成通过。
- `python scripts\manage.py typecheck`、`python scripts\manage.py routes` 和 `python scripts\manage.py build` 通过。
- 所有验证日志位于项目 `logs/` 目录。
- 本阶段不改变客户、跟进、提醒、任务、合同、订单、回款和统计页面的业务含义。

## Phase 2：安全和恢复验收

Phase 1 通过后实施：

- 四角色浏览器验收。
- 备份恢复演练。
- 文件访问、导出和下载权限检查。
- 账号停用、锁定、退出和会话失效检查。

## Phase 3：交付维护

Phase 2 通过后实施：

- 管理员和普通用户使用说明。
- 发布、回滚和数据库迁移说明。
- 日志、备份、权限和账号月度检查表。
- 已知问题与后续版本记录。

## 不在本计划内

- 新增销售业务功能。
- 新增商机、报价和产品目录。
- 重做前端页面风格。
- 升级基础框架大版本。
- 初始化 Git 仓库或伪造合并提交。
