# CRM 权限与数据范围矩阵

本文档对应当前代码权限契约。权限判断采用：页面入口、按钮、Route Handler、Prisma 数据范围四层同时校验。

| 模块 | 页面 | 页面权限 | 动作权限 | API | 数据范围 |
| --- | --- | --- | --- | --- | --- |
| 客户 | `/customers` | customer:view | 新增 customer:create；编辑/转移 customer:update | `/api/customers` | 管理员/财务全局；主管本人及下属；销售本人；受限角色为空 |
| 提醒 | `/reminders` | customer:view | 跟进 followUp:create；禁用/恢复 customer:update | `/api/reminders` | 按客户 salesId；计划跟进按 FollowUp.salesId 使用同一范围 |
| 统计 | `/statistics` | report:view | 只读 | `/api/statistics/*` | 订单、客户、回款、跟进均使用同一销售范围 |
| 电销 | `/telemarketing` | lead:view | 新增 lead:create；编辑/删除 lead:update；转客户 lead:convert + customer:create | `/api/telemarketing` | 当前操作人电销记录 |
| 订单 | `/finance/orders` | order:view | 新增 order:create；编辑 order:update；删除 order:cancel | `/api/finance/orders` | 按 Order.salesId；新订单沿用客户 salesId |
| 回款 | `/finance/payments` | payment:view | 新增 payment:create | `/api/finance/payments` | 按 Payment.order.salesId；写入前校验订单范围 |
| 财务报表 | `/finance/reports` | report:view | 只读 | `/api/finance/reports/summary` | 按 Order.salesId |
| 日报 | `/daily-reports` | report:daily:view | 提交 report:daily:create | `/api/daily-reports` | 按 DailyReport.userId |
| 任务 | `/tasks` | task:view | 创建 task:create | `/api/tasks` | 按 Task.assigneeId |
| 文件 | `/files` | file:view | 上传 file:upload；下载 file:download；删除 file:delete | `/api/files` | 按 File.uploadedBy |
| 合同备案 | `/customers/cooperating` | customer:view | 上传/删除 customer:update | `/api/contract-archives/*` | 按合同所属客户 salesId；运营负责人本人可只读 |
| 系统管理 | `/admin/users、roles、settings` | 各子页精确权限 | 按 user/role/setting 权限 | `/api/users、roles、settings` | 管理数据，不使用销售范围 |

## 角色范围

- 管理员：拥有权限点覆盖的全部数据。
- 财务：拥有权限点覆盖的全部数据；没有某项权限时仍返回 403。
- 销售主管：仅本人及递归下属的数据。
- 销售：仅本人及递归下属的数据；通常没有下属，因此表现为本人数据。
- 自定义受限角色：只有功能权限但没有已声明数据范围时，查询结果为空，详情和写入返回 403。

## 会话生效

服务端每次执行 `auth()` 时重新读取 ACTIVE 用户、角色和权限。角色撤权立即作用于 API；用户停用后旧会话不能继续调用受保护 API。中间件只负责页面入口的快速判断，最终授权以 Route Handler 为准。
