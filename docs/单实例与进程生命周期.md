# 单实例与进程生命周期

本文说明当前 CRM 的 stable/test 进程如何启动、识别、停止和恢复。动态检查只允许使用 `test` profile，不能把稳定库或稳定上传目录作为测试夹具。

## 本地命令

在项目根目录 `D:\Desktop\CRM系统代码 (2)\CRM系统代码` 执行：

```powershell
python scripts\manage.py start --profile test
python scripts\manage.py status --profile test
python scripts\manage.py stop --profile test
python scripts\manage.py runtime-test --profile test
```

stable 使用同样的命令，把 `test` 替换为 `stable`。启动、停止、状态和测试日志统一写入 `D:\Desktop\CRM系统代码 (2)\CRM系统代码\logs\<profile>\`。

## 实例记录

每个 profile 独立使用以下文件：

- `D:\Desktop\CRM系统代码 (2)\CRM系统代码\.runtime\<profile>\server.pid`
- `D:\Desktop\CRM系统代码 (2)\CRM系统代码\.runtime\<profile>\server.lock`

文件记录 `pid`、`profile`、`port` 和项目根目录。锁文件在创建服务子进程前以排他方式创建，服务进程生成后再原子写入正式 PID。stable 默认端口为 `3000`，test 默认端口为 `3001`，两个端口不能相同。

## 启动判断

启动前会同时检查记录文件、进程命令行、项目根目录、profile、端口和端口监听 PID：

- `running`：当前项目进程树正在监听对应端口。
- `starting`：当前管理进程已经取得锁，服务端口仍在初始化。
- `stale`：记录存在但对应进程已经退出；端口空闲时可以清理。
- `foreign_pid`：PID 已被其他进程复用，拒绝停止或接管活动实例。
- `port_conflict`：端口由未登记进程占用，拒绝启动和停止。
- `corrupt`：记录字段缺失、字段不一致或项目路径不匹配，活动端口存在时拒绝处理。

第二次启动同一 profile 会返回非零退出码，不会创建第二棵 CRM 进程树。stable 与 test 可以各运行一个独立实例，但必须使用不同端口、数据库、上传目录、日志目录和运行目录。

## 停止与异常恢复

停止只对通过项目路径和运行时命令校验的 CRM 进程树执行终止。端口仍被其他进程占用时不会删除活动实例记录，也不会误杀外部进程。服务异常退出后，下次启动在端口空闲时会清理陈旧 PID/锁；端口仍占用时必须先处理外部占用，再重新启动。

日志目录、上传目录、运行目录和构建目录在启动前会执行写入探针。日志无法打开、服务进程创建失败或服务未能监听端口时，会终止已创建的进程并清理 PID/锁文件。

## 服务器进程管理

服务器只使用 systemd 直接管理 Next.js，不再让 systemd 包装 PM2。模板位于 `D:\Desktop\CRM系统代码 (2)\CRM系统代码\scripts\deploy\crm@.service`，正式发布脚本会写入目标提交和版本，并把 stable 绑定到 `127.0.0.1:3000`。数据库连接、会话密钥和 OSS 凭据继续由项目环境文件加载，不写入服务模板或发布日志。

线上审计、备用端口验收、部署和回滚分别使用：

```powershell
python scripts\manage.py production-audit --profile stable
python scripts\manage.py production-stage --profile stable --artifact <发布包绝对路径>
python scripts\manage.py production-deploy --profile stable --artifact <发布包绝对路径>
python scripts\manage.py production-rollback --profile stable
```

同一时刻 stable 只能有一个 systemd 进程树监听 `127.0.0.1:3000`。候选验收使用独立备用端口，验收结束后必须停止候选进程并释放端口。

反向代理只能把 stable 流量转到 `127.0.0.1:3000`，测试流量转到 `127.0.0.1:3001`。不能使用同一端口同时承载两个 profile。
