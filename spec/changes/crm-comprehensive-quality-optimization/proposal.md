# Proposal: crm-comprehensive-quality-optimization

## Why

当前 CRM 已有销售业务雏形，但部分页面仍使用模拟数据或无真实动作按钮，请求、会话、权限、运行脚本和发布环境也缺少统一验收。此次变更不扩展新的销售业务字段，目标是让现有功能可操作、数据可验证、长时间使用可恢复，并让测试版与稳定版能够独立发布和回退。

## What

- 建立 stable/test 隔离、Git/备份门禁、统一脚本和单实例运行治理 | verify: 两个 profile 的端口、PID/锁、日志、数据库和上传目录可被脚本检查，重复启动被拒绝，稳定数据不被测试写入。
- 重构全局布局和超长页面，保留全部现有字段与 Ant Design 交互，缩短常用销售操作步骤 | verify: 18 个页面在桌面与移动视口无重叠，关键页面文件满足模块化约束，原字段和入口清单无缺失。
- 建立按钮契约并修复 mock、死按钮、权限不一致、统一请求、会话恢复和数据写入链路 | verify: 每个 active 按钮均由 Playwright 真实点击并验证 API、数据库、审计及失败状态，页面不再以成功提示代替持久化。
- 优化前端资源、API、Prisma 查询、连接管理、健康检查和服务端日志 | verify: 重新测量后的性能预算、慢查询检查、构建、健康检查和长时间稳定测试均通过且有日志证据。
- 建立 Next.js 15.4/React 19 测试通道、发布提升、回滚、权限矩阵、安全检查和客户运行文档 | verify: test 完整验收后方可 promote，回滚演练可恢复上一稳定版本，发布文档与脚本在 Windows/Linux 入口一致。

**Not in this change**: pymss/MSST、DDSP、SVC、GPU/音频模型移植；新增商机、报价、营销自动化等业务模块；删除现有销售字段；替换 Ant Design；使用生产数据作为自动化测试夹具。

## How

- 先处理旧 Spec、Git、备份和 stable/test 数据隔离，再允许任何写入测试；所有动作由 `scripts/manage.py` 和 `scripts/manage.sh` 统一记录到 `logs/`。
- 以按钮契约连接页面、权限、API、数据库和审计，mock 页面接入真实模型；非幂等写入不自动重试，失败必须明确显示并保留草稿。
- UI 继续使用 Ant Design，通过设计令牌、共享页面骨架和功能模块拆分统一体验；不引入第二套组件库。
- 性能以新基线和可执行预算为准；Next.js 15.4/React 19、ESM 配置先在 test 验证，通过 promotion 门禁后才进入 stable。

## Risk

- Blast radius: 18 个业务页面、38 个 API Route、认证权限、Prisma 数据访问、运行脚本和服务器发布配置均可能受影响。
- Risk: 环境配置错误可能让测试写入稳定数据；框架升级可能破坏认证或 Ant Design；页面拆分可能遗漏字段；统一重试可能重复写入。通过 profile 硬校验、字段清单、写操作禁重、真实 E2E 和分阶段提交控制。
- Rollback plan: 每个一级任务独立提交；数据库迁移前备份并验证恢复；stable 只接收通过门禁的 test 构建，失败时回退到上一提交、上一构建和兼容 schema，不删除原始数据。
