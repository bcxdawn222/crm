# Research: crm-code-audit-and-sales-form-flow

## Practices
- 管理后台的远程下拉项应由页面在打开或加载时请求真实数据，并在加载中、空数据、请求失败三种状态下给出明确反馈；只渲染一个没有选项来源的 `Select`，会让必填字段永远无法提交。现有项目使用 Ant Design `Form` 和 `Select`，因此优先沿用页面现有组件，不引入新的表单库。
- 页面状态筛选和状态展示必须使用 Prisma 枚举的真实值，中文文案只作为显示层。把显示文案对应到不存在的枚举值，会让列表筛选返回 400 或让状态标签无法匹配；状态映射应集中在页面常量中，并与 `prisma/schema.prisma` 的 `OrderStatus`、`TaskStatus` 对照。
- 负责人和客户选项属于受权限约束的业务数据，不能通过页面硬编码或让客户端自由传入任意用户 ID 来解决。选项接口应返回当前用户可访问的数据范围，创建接口仍需在服务端校验客户和负责人的存在性及权限。
- 两个页面都存在“页面可见但新增操作不能完成”的断裂，最小修复应优先恢复选择项、状态筛选和提交契约；不在本轮把订单、任务页整体改造成新的表格或状态管理框架。

## Constraints
- 订单页面由 `src/app/(dashboard)/finance/orders/page.tsx` 调用 `/api/finance/orders`；新增订单需要 `customerId`、`contractAmount` 和 `signDate`，服务端创建时将状态写为 `CONFIRMED`。页面客户 `Select` 当前没有 `options`，状态筛选仍发送不存在的 `PROCESSING`。
- 订单模型 `OrderStatus` 只有 `PENDING`、`CONFIRMED`、`DELIVERING`、`COMPLETED`、`CANCELLED`。因此“处理中”不能直接映射为 `PROCESSING`；本轮必须使用已有枚举含义，不能修改数据库枚举来迁就页面文案。
- 任务页面由 `src/app/(dashboard)/tasks/page.tsx` 调用 `/api/tasks`；创建接口需要 `assigneeId`，模型 `TaskStatus` 只有 `TODO`、`IN_PROGRESS`、`COMPLETED`、`CANCELLED`。页面负责人 `Select` 当前没有 `options`，状态筛选和状态标签仍使用不存在的 `DONE`。
- `/api/users` 当前只允许拥有 `user:view` 的用户访问。销售角色的权限映射没有 `user:view`，因此任务负责人不能简单依赖该接口而不处理权限边界；需要在设计阶段决定复用现有接口、扩展一个最小的任务负责人查询能力，或只允许当前用户自我指派。
- `/api/customers` 返回当前用户数据范围内的客户列表，但接口默认分页；订单表单需要明确选项加载的分页、搜索和空数据行为，不能假设一次返回全部客户。
- 创建任务的销售角色只有 `task:view`、`task:update`，没有 `task:create`；页面当前展示“创建任务”按钮，但服务端会返回 403。负责人下拉修复不能掩盖这个权限断裂，需同时决定销售是否应能创建自己的任务。
- 本轮沿用 TypeScript + Next.js + React + Ant Design + Prisma，不新增依赖，不改数据库模型，不修改客户、订单或任务历史数据，不执行删除性数据迁移。
- MySQL 当前未监听 `127.0.0.1:3306`，真实登录和业务接口回归仍受上一轮环境阻塞；本轮先补静态契约和可执行的接口/页面验证设计，数据库恢复后再执行真实数据回归。
- 当前工作区没有 `.git`；本轮不初始化仓库、不合并 `main`、不提交未知历史。

## Decided
- [DEC-7] 本轮只修订单和任务新增/筛选的最小可用链路，不做页面重构；来源 [TBD-0/上一轮 V-8]，决定依据是当前问题明确集中在空下拉和非法枚举，扩大到新状态管理会增加回归面。
- [DEC-8] 外部行业调研不作为本轮前置，按现有代码、Prisma 枚举和权限映射完成研究；来源 [TBD-0]，决定依据是这是内部契约修复，没有新依赖、技术选型或陌生业务领域。
- [DEC-9] 订单客户下拉采用现有 `/api/customers` 的分页和关键字参数，弹窗打开时加载第一页，输入关键字后重新查询；来源 [TBD-2]，auto，理由是复用现有数据范围和接口，能够处理客户量增长，回退只需恢复静态第一页加载，不新增依赖。
- [DEC-10] 任务权限按角色分层：销售可以创建只指派给自己的任务，主管和财务可以从其可访问的 ACTIVE 用户中选择负责人；来源 [TBD-1]，escalated，理由是页面已经向销售展示“创建任务”，让销售只能自我指派能恢复现有可见功能，同时保留主管分派任务的业务用途；如果错误，影响任务权限和用户可见范围，撤回路径是隐藏销售创建入口并恢复原权限映射。
